# 剧本标签清单（给编剧）

> 2026-10-30。**每一条都对着解析器验过**，不是按记忆写的。
> 一句话：**结构四件必须写，其余按需要**；写错的后果我都标出来了。

---

## 一、必须写的四件（缺一件就播不出来）

| # | 写什么 | 语法 | 不写会怎样 |
|---|---|---|---|
| 1 | **章** | `# CHAPTER 1｜章节标题`（也可 `# 第一章 标题`） | 整份稿子进不去（报「没有章节」） |
| 2 | **场景** | `# SCENE｜地点`（或 `# 场景｜地点`、`# 第三场｜地点`） | 没有场景卡；**没有落图的地方** |
| 3 | **正文** | `旁白：……` / `角色名：“台词”` / `你：“台词”` | 会被拼成一大段，或整章报"没有内容" |
| 4 | **章末选择** | `# CHOICE｜问题` + `#### A｜选项` `#### B｜选项` + **`# ·`** | 报硬错「章末没有 CHOICE」；**少 `# ·` 收尾，后面的内容会被算进最后一个选项** |

## 二、可选：交互的四种写法

| 写法 | 作用 | 会不会停下等玩家 |
|---|---|---|
| `# CHOICE｜问题` + `#### A｜…` | 章内/章末选择（**一章里最后一个 = 章末选择**） | 停（等选） |
| `⟦FREE\|问题\|选项1\|选项2\|选项3⟧` | 中段自由输入点（玩家也能自己打字） | 停（等说/选） |
| `⟦CALL\|角色名\|情境⟧ … ⟦/CALL⟧` | 一通电话卡 | **停**（已验：它是唯一会让剧情暂停等玩家的标签） |
| `⟦ITEM\|名字\|描述\|🔖⟧` | 道具卡 | **暂停约 0.9 秒**后自动继续 |

选项还能带效果：`⟦OPT|A|set:旗子;love:2⟧` —— 选了 A 之后打旗 / 加好感。

## 三、可选：引擎标签（按需，全都不影响节奏）

| 标签 | 作用 | 备注 |
|---|---|---|
| `⟦CHAR\|名字\|性别\|年龄\|立绘\|身份\|描述⟧` | 角色卡（性别写 `m`/`f`） | 取向靠它推断，缺了会告警 |
| `⟦ORIENT\|bg⟧` | 取向：`bl` / `gl` / `bg` | 不写我们按角色卡推 |
| `⟦BG\|槽位名\|地点⟧` | 给**上一个场景**挂背景图 | **前面必须有 `# SCENE`**，否则静默失效 |
| `⟦TIME\|04:17⟧` | 给上一个场景挂时间 | 同上 |
| `⟦BGM\|标签\|风格⟧` | 音乐 cue | 不改节奏 |
| `⟦CG\|槽位\|说明⟧` / `⟦VIDEO\|槽位\|说明⟧` | 插一张图 / 一段短片 | 插一条就过，**不停** |
| `⟦PHOTO\|标题\|说明⟧` | 照片卡 | 同上 |
| `⟦MG\|小游戏 id⟧` | 小游戏 | 同上 |
| `⟦SET\|旗子名⟧` | 打旗（记下"发生过"） | 后文用 `⟦IF⟧` 查 |
| `⟦IF\|旗子⟧ … ⟦ELSE⟧ … ⟦/IF⟧` | 条件播放（`⟦IF\|!旗子⟧` = 没打过） | 可嵌套 |
| `⟦GOAL\|这一章要立什么\|English⟧` | 章节目标（读者看到 + 角色知道） | 不写就退回用章末问题 |
| `⟦SECRET\|id\|秘密\|knows:谁\|reveal_from:第几章⟧` | 认知边界（角色不该知道的事） | 见下条 |
| `⟦REVEAL\|id⟧` | 在正文这一处提前解锁秘密 | 不写就按 `reveal_from` 章号解锁 |

## 四、三条**会静默出错**的坑（最重要）

| 坑 | 后果 | 正确写法 |
|---|---|---|
| **中文场景名不带 `#`** | 场景数还是 0，而且**那一行会当旁白显示给玩家** | `# 场景｜克罗斯酒店 · 417 套房`（英文 `SCENE｜` 不带 `#` 也行，中文必须带） |
| **`⟦BG\|…⟧` 前面没有 `# SCENE`** | 什么都不发生（不报错、不出图） | 每个 `⟦BG⟧` 紧跟在一个 `# SCENE` 后面 |
| **`# CHOICE` 少了 `# ·` 收尾** | 后面的正文被算进最后一个选项，玩家还没选内容就跑光了 | 每个 `# CHOICE` 块末尾加一行 `# ·` |

## 五、想控制节奏：写这几样就够

| 你想要的 | 怎么写 |
|---|---|
| **全剧多几次"停下"** | **多切章**（每章 = 一个播放批次，章末必停一次） |
| **一章内部也想停** | 加 `# CHOICE`（章内的）或 `⟦FREE⟧`，或 `⟦CALL⟧` 通话卡 |
| **某一句话停留久一点** | 把句子写长（停留 ≈ 字数 × 105 ms，最长 7 秒） |
| **换背景/换时间** | `# SCENE`（换卡，不停）；`⟦BG⟧`/`⟦TIME⟧` 只贴属性 |

> 参考量级：前几天那批 12 章，每章约 18 条正文 ⇒ 全剧 24 次"停"；
> 这周交的 1 章版本，每章约 35 条 ⇒ 全剧只有 2 次。**体感差别主要来自章数，不是场景数。**

## 六、受限词（会被内容闸拦下，整份不放行）

`性器` `勃起` `插入` `抽插` `内裤` `下身`
`erection` `crotch` `groin` `penetrat` `genital` `naked body` `nipple`

（"硬 / 热 / 湿 / 布料 / 腰"这些都不在名单里，写强度不受影响。）

## 七、取向：bg / bl / gl

| 写什么 | 效果 |
|---|---|
| `⟦ORIENT\|bg⟧` | 女性向（男女恋）。发现页那个徽章显示 **M/F** |
| `⟦ORIENT\|bl⟧` | BL（男男）。徽章显示 **BL** |
| `⟦ORIENT\|gl⟧` | GL（女女）。徽章显示 **GL** |

**不写也能上**，但我们按角色卡推：`你(f)` + 对手戏 `(m)` ⇒ `bg`；同性别 ⇒ bl/gl。
**写了但和角色卡矛盾** ⇒ 审核直接报错（例：写 bl 但角色卡是"你(f)+男主(m)"）。

⚠️ 取向决定**读者能不能看到这部剧**：发现页是按取向筛的。选「女性向」的读者看不到 bl 的作品，反之亦然。

## 八、视角：读者扮演谁（**没有专门的标签**）

系统不看标签，靠三件事自动判（`app51_import.js:61`）：

1. **`你：“台词”`** —— 写成"你"的人就是读者
2. **`【心理】`** —— 心声自动绑到"读者扮演的那个人"
3. **投票**：谁在最多选择分支里开口，谁就是读者；兜底 = 说话最多的角色

所以写法上要保证三件事：

```
⟦CHAR|你|f|22|f2|玩家角色|Victoria Vale，22，维尔集团第三代⟧   ← 玩家角色卡（性别 f/m 必须写对）
你：“门没锁。”                                                  ← 玩家台词用"你"
【心理】                                                        ← 心声（下一行写 “……”）
> “他为什么偏偏今晚回来？”
```

**关键一条**：让"你"出现在选择后果里（`#### A｜…` 后面的段落里也要有"你"的台词或动作）。
如果整章只有别的角色在说话，系统会把**说话最多的人**当成读者 —— 那就变成"读者在演男主"了。

其余角色有 ≥2 句台词才会进演员表；主要角色建议都写 `⟦CHAR⟧` 卡（性别决定取向推断）。

### 电话 `⟦CALL|角色名|情境⟧` … `⟦/CALL⟧`

- 弹一个**真语音通话卡**（走云语音后端，需要密钥配好）
- 里面写的台词是"他想说的意思"，不是要念的字面稿
- **必须 `⟦/CALL⟧` 闭合**，不闭合后面全被吞
- **它是唯一会让剧情停下等玩家的标签**（本轮验过）

# 第二部分：作品资料（`bible.json`）——标题 / 标签 / 背景 / 角色 / 素材

> 走「大纲版（自由模式）」的作品，除正文之外还要交一份**作品资料**。
> 我们这边已经有一份可照抄的活样板：`art/official/w_scmvv3sk58b2935cc9b2.bible.json`（18 章 142 场）。
> 下面每一条都是**代码里真读的字段**，不是建议。

## 十、标题 / 简介 / 分类标签

| 字段 | 必填 | 写什么 | 不写会怎样 |
|---|---|---|---|
| `title{zh,en}` | ✅ | 作品名（中英各一） | 卡片没有标题 |
| `hook{zh,en}` | ✅ | **一句话钩子**（发现页卡片上那行小字） | 卡片只有标题 |
| `premise{zh,en}` | ✅ | 故事简介 2–4 句 | 详情页空着 |
| `intro{zh,en}` | 可选 | 开场白 | 用 `premise` 顶 |
| `tags[]` | ✅ | **分类标签，最多 8 个**：题材词（豪门/悬疑/校园）、基调词（危险/温柔/慢热）、卖点词（18+/三角/四结局） | 发现页没有标签条 |
| `orient` | ✅ | `bg`（男女）/ `bl`（男男）/ `gl`（女女） | 按角色卡推，推不出就用默认 |

> `tags` 在 App 里是**用户筛选的依据之一**，写具体的题材词比写形容词有用。

## 十一、故事背景与世界设定

| 字段 | 必填 | 说明 |
|---|---|---|
| `world` | ✅ | **故事背景**：地点、势力、规则、禁忌。一段话，写"这个世界怎么运转"（例：家族体面高于真相；每一句情话都可能被录音） |
| `style` | ✅ | **写法与语气规则**：给导演和角色看的。写"旁白只写画面与动作，绝不包含对话""每轮推进一小步，不强迫玩家做选择"这类 |

这两段是**导演智能体每一轮都会读**的东西 —— 它们决定"这部剧讲起来是什么味道"，比任何单个标签都重要。

## 十二、角色：简要介绍 + 完整卡

### 玩家

```json
{"key":"me", "name":{"zh":"你","en":"You"}, "gender":"f",
 "role":{"zh":"Victoria Vale，22，维尔集团第三代；参与品牌与公关；不是审计师",
         "en":"Victoria Vale, 22, third generation of the Vale Group"}}
```

### 角色卡（每个可攻略/在场角色一张）

| 字段 | 必填 | 说明 |
|---|---|---|
| `key` | ✅ | 英文小写 id（`adrian`）—— **场景的 `present` 和立绘文件名都用它** |
| `name{zh,en}` | ✅ | 全名 |
| `short{zh,en}` | ✅ | 别人怎么叫他 |
| `gender` / `age` | ✅ | `m`/`f`；年龄数字 |
| `tier` | ✅ | `lead`（主线可攻略）/ `secondary`（次级） |
| `romanceable` | ✅ | true/false |
| `love0` / `trust0` | ✅ | 初始好感 / 信任（0–100） |
| `role{zh,en}` | ✅ | 一句话身份 |
| `bio` | ✅ | **形象锚点**：身高、发色发型、眼睛、疤/旧伤、气味、穿衣五套 —— 生成立绘全靠这一段 |
| `personality` | ✅ | 性格：他要什么、怕什么、怎么表达情绪 |
| `voice` | ✅ | 说话方式：句长、口头习惯、紧张时怎么变 |
| `want` / `fear` | ✅ | 他想要的 / 他怕的（推动场面的两个引擎） |
| `boundaries` | 可选 | 他不会做的事 |

> **`bio` 写得越具体，生成的角色立绘越稳定**（同一角色跨章要长得一样，只能靠这段描述固定特征）。

## 十三、章节与场景（大纲怎么变成剧情）

```json
"chapters":[{"n":1,"title":{"zh":"417 号房间"},
  "goal":"这一章要立什么",
  "card98":{"adrian":{"knows":["…"],"unknown":["…"],"beliefs":["…"],
                      "relation":"他此刻对你的态度","goal":"他这一章想要的","speech":"他的说话习惯","growth":[]}},
  "scenes":[{"id":"c01s01","place":{"zh":"酒店走廊 04:17","en":"hotel corridor 4 a.m."},
             "beat":"门本就没锁；绿灯；你手里攥着匿名消息",
             "present":["adrian"], "script":[], "opts":[]}]}]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `scenes[].id` | ✅ | **场景 id**（`c01s01`）—— **场景图文件名要用它** |
| `scenes[].place` | ✅ | 场景名（会显示在顶部） |
| `scenes[].beat` | ✅ | **一句话的戏**（= 大纲那列「内容与钩子」）。导演按它演 |
| `scenes[].present` | ✅ | 这一场在场的人，写 `key`。**空着导演就自己猜** —— 想让谁在场，在 `beat` 里写出名字，或直接填这里 |
| `scenes[].script` | 可选 | 逐字演出（`{who,k:"act"/"say",zh,en}`）。留空 ⇒ 全部由 AI 演 |
| `scenes[].opts` | 可选 | 这一场的选项 `[{k:"say"/"act"/"silent", t:"…"}]`。留空 ⇒ 靠自由对话推进 |
| `card98` | 可选但推荐 | 每个角色在这一章的**认知边界**（他知道什么/不知道什么/他怎么看你） |
| `endings[]` | ✅ | 结局：`{id,name{zh,en},condition,text}` |

## 十四、图片与视频：**命名是硬约定，不是随便起**

素材靠一份映射表 `art/official/<作品id>.json`，格式：

```json
{ "bg_c01s01": "art/official/<作品id>/v1/bg_c01s01.jpg",
  "char_adrian": "art/official/<作品id>/v1/char_adrian.jpg",
  "cover": "art/official/<作品id>/v1/cover.jpg" }
```

**槽位名（左边那个 key）必须按下面来**，代码是按前缀取的：

| 素材 | 自由模式（大纲版） | 逐字剧（正文版） |
|---|---|---|
| 场景图 | **`bg_<场景id>`**（`bg_c01s01`） | 剧本里 `⟦BG\|任意名⟧` 写什么就用什么 |
| 角色立绘 | **`char_<角色key>`**（`char_adrian`） | 角色卡里的立绘名 |
| 插画 / 特写 | ❌ 不支持 | `⟦CG\|任意名\|说明⟧` |
| 视频 | ❌ **不支持** | `⟦VIDEO\|任意名\|说明⟧` ← **视频只有这条路能显示** |
| 封面 | `cover` / `poster` | 同 |

### 规格（我们这边实测过的）

| 类型 | 规格 | 体积 |
|---|---|---|
| 场景图 / 立绘 | **竖屏 941×1672**（比例 9:16） | PNG ≈ 2 MB → 存 JPG(q82) ≈ **230 KB** |
| 视频 | **1080×1920 · h264 + aac** | 10 秒 ≈ 5 MB |
| 封面 | 竖屏同比例 | ≈ 200 KB |

### 生图提示词要求

- **英文写**，只描述画面：人物（发型/眼睛/疤/服装固定特征）+ 动作 + 环境 + 光线 + 镜头（`medium shot` / `over the shoulder`）
- **竖屏构图**（`vertical 9:16 portrait composition`）
- **不要**在提示词里要求出现文字、标题、水印（画面里出字会毁掉整张图）
- 同一角色跨图**必须复用同一段形象描述**（`bio` 那段），否则每张长得不一样
- 场景图优先"**空场景**"（只有环境），人物交给立绘叠上去

## 十五、⚠️ 这三批稿子的素材名对不上（实例，给他们看）

他们交的 59 张图叫：`bg_01…bg_20` / `hl_01…hl_10` / `portrait_adrian…` / `prop_01…prop_20`

而自由模式要的是：`bg_c01s01` / `char_adrian` / `cover`

⇒ **现在一张都显示不出来**（不报错、也不提示）。两条路选一条：
1. 按新规则**重命名/重新出图**（`bg_<场景id>`、`char_<key>`）
2. 走**逐字剧**那条路，然后用 `⟦BG|bg_01⟧` 把槽位名写进正文（这样原文件名就能用）
