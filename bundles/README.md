# 剧本包 + 静态接口（给前端）

> 2026-10-31。姜老师那边要「剧本 + 图片 + 视频打包，接口留给前端自己解析」。
> 下面是他需要知道的一切：**地址、包里有什么、怎么读**。

---

## 一、两个地址（静态文件，不用改 API）

```
https://www.miru.plus/bundles/index.json           ← 清单：有哪些包、版本、大小、sha256
https://www.miru.plus/bundles/<work_id>.zip        ← 单部作品下载
```

**为什么用静态文件而不是新 API 路由**：可直接被 CDN 缓存、不占函数调用、也不需要动 `api/`（少一处冲突面）。
将来要"按需生成"再上接口，现在的形态不挡路。

## 二、包里有什么

```
<work_id>/
  manifest.json     ← 版本 + 标题 + 取向 + 标签 + 章节数 + 每个文件的 path/bytes/sha256
  script.md         ← 剧本原文（MIRU DSL 文本，就是数据库 pack.script 那一份）
  bible.json        ← 故事圣经（只有大纲型作品有）
  art.json          ← 素材槽位 → 包内路径（槽位名是剧本/圣经里引用它的名字）
  art/<槽位>.jpg    ← 素材本体
  art/<槽位>.mp4    ← 视频
```

`manifest.json` 的形状：

```json
{
  "bundleVer": 1,
  "scriptVer": 2,          // 语法版本号：我们改语法就 +1，你们据此判断要不要跟进
  "workId": "w_…",
  "packVer": 1793360208030,
  "mode": "script | bible",
  "chapters": 1,
  "meta": { "title": "…", "hook": "…", "orient": "bg", "tags": ["…"] },
  "files": [ { "path": "script.md", "bytes": 3438, "sha256": "…" } ]
}
```

## 三、两条路，看 `mode` 字段

| `mode` | 剧本在哪 | 怎么玩 |
|---|---|---|
| `script` | `script.md`（DSL 文本，逐字剧） | 前端自己解析成事件流，按顺序播；玩家说话时模型接管 |
| `bible` | `bible.json`（故事圣经） | 导演按「场景锚点」演，玩家自由对话，点「继续」才推进 |

**同一部作品可能两个都有** —— `script` 是逐字剧，`bible` 是全篇大纲，前端按自己需要取。

## 四、解析器不在包里（这是有意的）

包**只含数据**。解析规则在《剧本标签清单（给编剧）》里（必填四件 / 交互四种 / 引擎十三种 / 三条静默坑）。
我们这边**不承诺**与你们自研的解析器保持行为一致 —— 但：

- `manifest.scriptVer` 会随语法变化 **+1**
- 校验用 `files[].sha256`，不要用 `bytes` 判完整性

## 五、素材命名（对不上就不显示，且不报错）

| 用途 | 自由模式（bible） | 逐字剧 |
|---|---|---|
| 场景图 | `bg_<场景id>`（`bg_c01s01`） | 剧本里 `⟦BG|任意名⟧` 写什么就用什么 |
| 角色立绘 | `char_<角色key>`（`char_adrian`） | 角色卡里的立绘名 |
| 插画/特写 | — | `⟦CG|任意名⟧` |
| 视频 | — | `⟦VIDEO|任意名⟧`（**视频只有逐字剧能显示**） |
| 封面 | `cover` / `poster` | 同 |

素材本体在 Vercel Blob，`art.json` 里同时给了包内路径；两个来源内容一致（sha256 可核）。
