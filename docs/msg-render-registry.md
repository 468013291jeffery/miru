## 一、现状（实测）

`msgHTML` 被 **19 层**包装（`node tools/msghtml-triage.mjs`）。形状与 pkDirective 不同：

| 形状 | 层数 | 例子 |
|---|---|---|
| **按 `m.k` 分发**（认领某类型就自己渲染，否则交给内层） | 10 | `if(m.k==="box") return boxHTML(...)` |
| **先渲染再加工**（`const h = 内层(); …改动…; return h`） | 4 | `app73` 给它挂上工具条、`app98` 改写收尾 div |
| **条件改写入参**（改 `m.txt` 后交给内层） | 5 | `app26` / `app34` 把玩家那句换成别的话 |

## 二、类型认领图（`node tools/msghtml-kinds.mjs`）

```
act      app16_story2 ×2, app94_official2      ← 3 层
box      app16_story2 ×2, app94_official2      ← 3 层
think    app16_story2 ×2                       ← 2 层
say      app17_custom, app26_turns, app34_hints, app73_features   ← 4 层
event / intro / scene            app16_story2
vn96                             app96_social
xtitle / xmoney / xpost / xanchor app23_heir
```

**4 个类型被多层认领。** 但要读准：其中多数是**带条件的**
（`if (m.pk && m.k==="say" && …)`），所以它们不是"互相覆盖"，而是"按条件接力"。
**真正的风险不是冲突，是不可预测**：一条消息走哪条渲染路径，取决于加载顺序 × 一堆积木式的条件，
而没有任何地方写着"这些条件合起来的结果是什么"。

## 三、要做成的形状

```js
MSGKIND.add('box',   function(m, i, th){ … });   // 类型 → 渲染器（一个类型一处）
MSGKIND.add('event', function(m, i, th){ … });
…
MSGKIND.post('tools73', function(h, m, i, th){ …; return h });   // 后处理（拿到已渲染的 HTML 再改）
MSGWRAP.add('stage-dir', function(m){ …; return m });            // 改写入参（返回新的 m，或原样返回）
```

分发顺序固定：`wrap（改入参） → kind 表（渲染） → post（改输出）`。
三类分开，**每类里顺序仍然可读**，而且"某类型有两个渲染器"从此是可检测的。

## 四、迁移顺序（每步可回滚、都有判据）

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 | 立 `MSGKIND`，**只登记不改行为**（与当天 `app109_pkdirect.js` 同法） | `msghtml-kinds.mjs` 的图与表逐条一致 |
| 2 | 把 **无条件**的 5 层搬进表（`event` / `intro` / `scene` / `vn96` / `x*`） | 真浏览器 0 uncaught；钩子数不变；消息渲染快照逐条一致 |
| 3 | 搬**条件型**（`say` / `act` / `think` / `box`）—— 每层读一遍条件再搬 | 同一个线程里这四类消息的 HTML **逐字节**与迁移前一致 |
| 4 | 后处理与改入参两类独立立表 | 同上 |

**第 2 步之前必须先做一件事**：写一个「消息渲染快照」工具——把 `th.msgs` 里每种类型的样例各渲染一次，
存成文本；迁移前后各跑一次，**逐字节 diff**。没有这个对拍，第 3 步就是在猜。

## 五、为什么今晚没有动

- 这是**每条消息都走**的路径，`renderChat` 的 22 个钩子也依赖它；一次搬错 = 全站消息变形。
- `say` / `act` / `think` / `box` 这四类带条件，**必须先有逐字节对拍**（见上），否则"看起来对"不算数。
- 剧本指令那次能一次搬完，是因为形状统一（`return next(...)`）；这里形状有三种，混着搬会出事故。

## 六、给下一个执行者的两句话

1. **先造对拍工具，再动一行代码。** 判据是「同一批样例前后 HTML 逐字节相同」，不是"看着还行"。
2. **表里要能表达"条件"**：条件写进各自的渲染器里，**不要**写成分发器的一部分 ——
   分发器一旦开始懂业务条件，它就变成了第 20 层包装。
