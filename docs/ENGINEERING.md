## 二、我们缺的（按代价排序）

### ① 空 catch —— 存量 **616 处 / 100 个文件**（最痛）

Mythica 第 7 条明令禁止裸 `except`。我们的 JS 版同一个病：`catch(_){}`。

**代价是实测的**：2026-10-27 一晚**三次**静默失败全是它——

| 事故 | 空 catch 干的事 |
|---|---|
| `[object Object]` 上屏 | 取值失败不吭声 |
| 剧本队列 | 空 beat 被静默跳过 |
| UI 调度器 | `U` 不在作用域 → 每次调用都抛 → 吞掉 → **钩子一次没跑，界面毫无异常** |

**已落地**：`tools/empty-catch-check.mjs`（基线与闸，新增必须 `--write` 显式确认）。
**下一步**：从最集中的文件开始清（`app3_chat` 49 · `app94_official2` 37 · `app45_rel` 19 …），
清一处的判据 = **失败要有可见出口**（日志 / 计数 / 用户可见提示），不是「让它继续静默」。

### ② 健康汇报（运行时计数**落盘**）

三件套里我们有「门禁 + 运行时防御」，缺第三件：**定期自动汇报，grep 就能发现异常**。
今晚所有计数器（`__turn` / `__save` / `__ui` / `__pkst`）只活在内存与控制台 ⇒ **她玩的时候没人看 = 没有**。

**已落地**：
- `source/src/app107_health.js` —— 每 30 秒 + 页面隐藏/离开时拍一张，写 `localStorage["miru_health"]`；
  本地开发（127.0.0.1/localhost）**直接 POST `/__health` 落盘** → `.browser-health.json`
- `tools/read-health.mjs` —— 人读，并对四类异常给退出码 1（回合冲突 / 钩子失败 / 非法迁移 / 空写比例过高）

实测输出（2026-10-27 06:17）：
```
回合冲突 0 · 存档 2 次 · 渲染 0 次/钩子 22 个 · 钩子失败 0 · 非法迁移 0 → 全绿
```

### ④ ≥5 参数用结构化对象

JS 里对应的是「别写 `f(a,b,c,d,e,f)`，写 `f({...})`」。**未量**（还没数过签名长度分布）。
做法：写一个 `tools/signature-census.mjs` 数一遍，超过 5 个位置参数的列出来，按出现频率决定要不要改。

## 四、判定「这条要不要做」的统一问法

1. 它治的病，**今晚发生过吗**？（发生过 ⇒ 有读数可对照；没发生 ⇒ 先记「未量」）
2. 有没有**可数的判据**？（没有 ⇒ 写出来的只是态度）
3. 做完之后，**谁能发现它退化了**？（没人能发现 ⇒ 等于没做）
