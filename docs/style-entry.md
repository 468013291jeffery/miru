## 二、三个被打破的预期

**① 「样式是按需注入的，所以拼不成静态表」—— 这一屏上不成立。**
2.5 秒和 14 秒两次快照的**序列指纹一模一样**（`7471fcc8`），说明首页上没有任何"晚到"的注入。
⚠️ 射程：只量了**首页**。所有 sheet / 弹层有没有按需注入的 CSS，还没量 —— 别把这一句读成全站结论。

**② 重复定义的主体不是"58 个文件各写各的"，而是基础样式表自己叠自己。**
81 个重复里 **72 个在同一个 sheet 内**，最大的几组（`.dkwrap` / `.dk` / `.dkc` 各 ×5，
`.story` / `.dkc h2` / `.dkc p` 各 ×4）全都落在 `sheet 0` = `shell.html`。
去 `shell.html` 里数一遍就能看见：`.dkwrap` 写在 411 / 509 / 734 / 859 / 881 五行。
⇒ **这是 CSS 版的猴补丁**：改样式不是改那一行，是在文件后面再追加一段覆盖它。
「改了这里坏那里」的机制在这里，不在"文件太多"。

**③ 真正会打架的只有 9 个，而且都是「注入层覆盖基础层」。**
9 个跨 sheet 重复的选择器（`.shprev` / `.shgrid` / `.chlist` / `.fxshake` / `.cam` / `.chh` …）
全部是 ×2，一方恒为 `sheet 0`。所以顺序风险是**单向的**：注入层永远赢基础层，
只要它俩同时在场。这比"19 层谁包谁"简单得多 —— 它不需要表，它需要**别重复定义**。

## 三、这把尺子自己的三个错（都已被抓住，记在这里免得下一个人再撞）

1. **切片压掉了空白** ⇒ 36 字符的探针在源码里对不上，报出 8 个假的「找不到来源」，归因率卡在 57/65。
   改成"取一个不含换行、首尾无空格的窗口、**一个字符都不改**"之后，65/65。
   ⇒ 判"归因失败"之前，先确认**我的探针是不是原文的一部分**。
2. **按 `file:line` 比文件** ⇒ 字面量归因给出的是 `a.js:28`，而"这一屏有没有这个文件"比的是 `a.js`，
   于是那个文件里所有其它注入点都被误判成「没生效」，报出 26 处（真实 1 处）。
3. 常量起名 `URL` 遮住了全局构造函数 ⇒ `new URL(import.meta.url)` 直接抛
   `TypeError: URL is not a constructor`，而报错行号指向下一行。

## 四、为什么这一轮不动手：这里要的闸不是"文本一致"

前面两轮的判据都是**形状**：19 种消息的 HTML 逐字节一致。样式**不能**这么验，因为
「把 5 次 `.dkwrap` 并成 1 次」这个动作**必然改变 CSS 文本**，而它可能正是对的。

样式版的判据只有一个：**生效值不变** ——

```
一批探针元素 × 一批属性 → getComputedStyle 取值 → 逐字节快照
搬迁前后必须完全一致；且每个探针元素都必须有非空读数（空值 = 这个探针根本没匹配上）
```

这条闸现在**不存在**。没有它，"合并重复定义"这件事既不可回滚也不可验收 ——
和 10-27 白天那次一样：`app16` / `app18` 两层一直是死的，而逐字节对拍照样全绿。

⇒ 顺序固定：**先造 computed-style 快照，再动第一行 CSS。**
（这条已经写进 `docs/msg-render-registry.md` §6 第 1 句，只是换了个对象。）

## 五、做的时候注意（现在不用做，但别忘）

- **不重排注入顺序**：65 个 `<style>` 的先后就是层叠顺序，任何"整理"只要动了顺序，就等于动了样式。
- **不合并条件注入**：`app92_mustlogin.js:13` 那种 `if (…)(function(){…})()` 是有条件的，
  拼进静态表会让它在不该出现的时候出现。
- **不动 `creator_embed.js` 里那段**：那是嵌入的 Creator 页面自己的 HTML，不是本页的样式。
