## 二、三个被打破的预期

**① 「样式是按需注入的，所以拼不成静态表」—— 这一屏上不成立。**
2.5 秒和 14 秒两次快照的**序列指纹一模一样**（`7471fcc8`），说明首页上没有任何"晚到"的注入。
⚠️ 射程：只量了**首页**。所有 sheet / 弹层有没有按需注入的 CSS，还没量 —— 别把这一句读成全站结论。

**② 重复定义的主体不是"58 个文件各写各的"，而是基础样式表自己叠自己。**
81 个重复里 **72 个在同一个 sheet 内**，最大的几组（`.dkwrap` / `.dk` / `.dkc` 各 ×5，
`.story` / `.dkc h2` / `.dkc p` 各 ×4）全都落在 `sheet 0` = `shell.html`。
去 `shell.html` 里数一遍就能看见：`.dkwrap` 写在 411 / 509 / 734 / 859 / 881 五行。
⇒ **这是 CSS 版的猴补丁**：改样式不是改那一行，是在文件后面再追加一段覆盖它。
「改了这里坏那里」的机制在这里，不在"文件太多"。

**③ 真正会打架的只有 9 个，而且都是「注入层覆盖基础层」。**
9 个跨 sheet 重复的选择器（`.shprev` / `.shgrid` / `.chlist` / `.fxshake` / `.cam` / `.chh` …）
全部是 ×2，一方恒为 `sheet 0`。所以顺序风险是**单向的**：注入层永远赢基础层，
只要它俩同时在场。这比"19 层谁包谁"简单得多 —— 它不需要表，它需要**别重复定义**。

## 三、这把尺子自己的三个错（都已被抓住，记在这里免得下一个人再撞）

1. **切片压掉了空白** ⇒ 36 字符的探针在源码里对不上，报出 8 个假的「找不到来源」，归因率卡在 57/65。
   改成"取一个不含换行、首尾无空格的窗口、**一个字符都不改**"之后，65/65。
   ⇒ 判"归因失败"之前，先确认**我的探针是不是原文的一部分**。
2. **按 `file:line` 比文件** ⇒ 字面量归因给出的是 `a.js:28`，而"这一屏有没有这个文件"比的是 `a.js`，

3. 常量起名 `URL` 遮住了全局构造函数 ⇒ `new URL(import.meta.url)` 直接抛
   `TypeError: URL is not a constructor`，而报错行号指向下一行。

## 四、判据不是"文本一致"：生效值快照（已造好）

前面两轮的判据都是**形状**：19 种消息的 HTML 逐字节一致。样式**不能**这么验，因为
「把 5 次 `.dkwrap` 并成 1 次」这个动作**必然改变 CSS 文本**，而它可能正是对的。

样式版的判据只有一个：**生效值不变**。

```
node tools/style-computed-snapshot.mjs            # 拍基线（改样式之前/之后想重定基准时才用）
node tools/style-computed-snapshot.mjs --check    # 与基线逐格比（check-all 里跑的是这一种）
```

装置：`tools/style-computed-snapshot.html`（探针页）+ `tools/style-computed-baseline.json`（基线）。
**30 个探针 × 26 个属性 = 780 格**，探针以合成元素注入（不依赖 App 当前显示哪一屏，
不受登录态/章节进度影响）；覆盖 census 里重复定义的重灾区（`.dkwrap/.dk/.dkc/.story/.chh/.cam`）
加主路径（`.m-row` / `.m-box lb` / `p.bac` / `.mquick` / `.sheet` / `.xmoney` / `.it101` …）。

**这条闸靠三条臂站着，缺一条就是摆设：**

| 臂 | 判什么 | 会不会自己假绿 |
|---|---|---|
| ① 与基线逐格比 | 780 格逐字节相同 | 会 —— 如果探针的祖先 `display:none`，所有值都是空串，于是"全空但一致" |
| ② 空值即红 | 任一属性读出空串 ⇒ 红 | 这是防 ① 的 |
| ③ 探针名字集合一致 | 少一个探针 = 红 | 防"删掉那个探针让它绿" |

**证据（不是"看着对"）**：
- 两次独立浏览器跑 → 780 格逐字节相同（尺子自洽）
- 变异：把**第 881 行那条真正生效的** `.dkwrap`（`padding:0`）改成 `padding:3px`
  → 红 **8 格，全在 `dkwrap · padding-*`**；还原后复绿
- ⚠️ 变异**必须打在生效的那一条上**：同名的 `.dkwrap` 在 411/509/734/859/881 有五条，
  改前面四条里的任何一条都不会红（被后面的覆盖）—— 那会让人误判"闸没用"

**改样式时的动作**：改 → `--check`。红了先看是哪一格：**多数红是真的**；
只有当这次改动**本来就该改样子**时，才重拍基线（`--write`），并在提交信息里写清"样子变了，我认"。

### 第一刀（已做，2026-10-27）

`shell.html` 里五条 `.dkwrap`（411 / 509 / 734 / 859 / 881）并成一条，**780 格一格没变**。

合并后的那一行（按"谁最后赢"取值）：

```css
.dkwrap{position:relative;margin-top:0;padding:0;
        background:radial-gradient(60% 70% at 50% 45%,rgba(156,132,224,.22),transparent 70%);
        container-type:inline-size}
```

**两道我在这件事上自己撞的坑（都不是样式问题）：**

1. **.NET 正则的 `$` 在 CRLF 文件上匹配不到行尾** —— `^\.dkwrap\{…\}$` 对 `…}\r\n` **不匹配**
   （`$` 落在 `\r` 之后）。于是"替换成合并版"那一步静默没执行，而前面四条删除**执行了** ⇒
   文件变成"少四条、也没有合并版"。修法：`(?m)^…` + **显式 `\r?\n` / `[regex]::Escape($eol)`**。
2. **`… | Select-Object -First N` 之后 `$LASTEXITCODE` 不是被截断那条命令的**（管道提前停止 ⇒ 取到上一个命令的 0）。
   我拿它当"红了就自动还原"的判据 ⇒ 闸红着、脚本却走了成功分支、文件留在半改状态。
   ⇒ 判退出码时**输出先落文件**（`Tee`），再从文件读；别在管道尾巴上判。

这两条都不是"样式难改"，而是**改样式的自动化脚本自己不可信** —— 而它们恰好都被闸抓住了
（`position: static` / `background: none` / `container-type` 丢掉导致 `.dk` 的 cqw 基准从 101.25px 变成 131.25px）。

### 第二刀：批量并 60 个（已做）

先写了一个**只读**判定 `tools/css-dup-analyze.mjs`，把「能不能机械并」拆成三条可查的条件：

| 条件 | 为什么 |
|---|---|
| 上下文相同 | `@media(max-width:600px)` 里那条只在窄屏生效，并进顶层就永久生效了 |
| 没有 shorthand/longhand 交叠 | `padding:10px` 与 `padding-top:3px` 同时出现时，「后来的赢」只对**同名**属性成立 |
| 中间没有同特异性、可能匹配同一元素的规则 | 把合并版挪到最后一条的位置，会让中间那条对某些属性的胜负翻转 |

判定结果：**A 档 60 个可机械并 / B 档 14 个需人看**（B 档的理由逐条打印，例如
`.m-event` 跨 `@media(prefers-reduced-motion:reduce)`、`.dkc p` 与 `.dkc h2` 中间夹着同特异性规则）。
`--apply` 只动 A 档：把最后一条的声明块换成合并体（按「后来的赢」），更早的整条删掉。

**结果**：`shell.html` 170457 → 166855 字符，重复定义的选择器 **74 → 14**（剩下的全是 B 档），
三条判据同时过：生效值快照 **780 格逐字节一致** · `check-all` **39 套全绿** · 真页面加载 **0 uncaught**。

#### 分档最后定成三档（第二版把 7 个「不是债」的东西从待办里摘了出来）

第一版只有「可机械并 / 需人看」两档，于是 14 个待办里混进了 7 个**根本不该动**的：

```
A 档（可机械并）3      .dkc.on · .m-act.me · .cbimg .cbv.on      ← 已并
B 档（同上下文、需人看）4  .status · .htabs · .story .av · .m-think.me   ← 全是 shorthand 交叠，决定不并（见下）
C 档（条件变体，不是待办）7  .m-event · .fdesc · .fside · .device · .fxshake · * · html,body
```

**C 档为什么不并**：它们是同一个选择器在不同 `@media`/`@supports` 下各写一份 —— 窄屏把 `.fside` 的
`bottom` 从 330px 改成 260px、`reduce-motion` 把 `.fxshake` 的 `animation` 关掉、宽屏给 `.device` 加圆角与阴影。
这不是"补丁叠补丁"，是**写在一起的条件覆盖**（多数就写在同一处上下两行）。并掉它等于把条件覆盖压平。

**B 档这 3 个为什么也不并**（`.status` / `.htabs` / `.story .av` 的 shorthand 交叠）：
要并就得把 `padding:0` 展开成 `padding-top/right/bottom/left`、把 `border:1px solid` 展开成三种 width/style/color ——
**代码可读性掉得比"少一处重复"值钱**。这里选择承认重复、并把理由写在这里，而不是硬并。

**判定工具的第二版又修了一处误判**：判「中间夹着同特异性规则」时，两个选择器只要共享一个类名就算
"可能匹配同一元素"。可 `.dkc.on` 与 `.wtki.on` 共享的只是一个状态类 `on`（全文件上百条规则都用它），
现实中没人把 `dkc` 和 `wtki` 挂到同一个元素上。加了**泛化度**：被 ≥12 条不同选择器用到的类名视为状态类，
不能当作"能匹配同一元素"的证据。于是 `.dkc.on` / `.m-act.me` / `.cbimg .cbv.on` 从「需人看」升到「可机械并」。

**这个判定工具自己错了四次，四次都是"我想当然了"**（都记在代码注释里）：
① 用「属性名前缀包含」判 shorthand 交叠 ⇒ 把 `border ⊃ border-radius`、`flex ⊃ flex-direction` 报成交叠，
而这两对根本不相干；② 把 `@keyframes` 里的 `from`/`to`/`0%` 当成了选择器 ⇒ 报出「`to` 被重复定义 18 次」这种纯噪声；
③ 判「中间夹着规则」时只看属性、没看选择器能不能匹配同一个元素 ⇒ `.dkc p` 被 `.dkc h2` 判成冲突；
④ 修了 ③ 之后又把**状态类共享**当成了"能匹配同一元素"的证据 ⇒ `.dkc.on` 被 `.wtki.on` 判成冲突。

## 五、死样式：和「死层」同一套判据（已造尺子，**还没删任何东西**）

`node tools/css-dead-rules.mjs` —— 在真页面上给每条 CSS 规则的选择器跑一次 `querySelectorAll`，
做**两次查询**来区分「死了」和「只在某个状态才有」：

```
raw     = querySelectorAll(sel).length          // 原样查，含 ::after 之类会抛
relaxed = 剥掉伪类/伪元素之后再查一次            // :hover / :disabled / ::after / :has
```

| 档 | 判据 | 读数（首页这一刻） |
|---|---|---|
| 活 | raw > 0 | 42 |
| 状态型 | raw = 0 但 relaxed > 0 | 2 |
| 此刻没元素 | 两次都 0 | 2690 |

**2690 不是"死代码"** —— 这是多屏应用，界面这一刻只显示首页。所以再按「有没有代码能造出这个类名」分四档：

```
46 条  真死候选（类名/id 在 JS 里从未出现过，也没有拼接前缀）
 0 条  可能拼接（前缀 `xx-` 在 JS 里出现过、完整名搜不到 ⇒ 先留着）
 6 条  没法按类名归因（`:focus-visible` / `*` / 纯标签）
2638 条 源码里有人用，只是此刻不在屏上（正常）
```

**这把尺子自己错了三次，每次都是"分母"的问题**：
① 第一版把 2690 条全叫「死候选」——分母是**一屏**，结论却像在讲全站；
② `cssText` 先被截到 200 字符、再拿它算长度 ⇒ 体积排序全是 200，等于没排；
③ 归因只看 `.class` 不看 `#id` ⇒ `#chTxt` / `#cbImg` 这类 id 规则全被判成"没人用"（真死候选一度虚高到 94 条）。

**变异验过**：把 `.status` 这条活规则的选择器改成 `.zzz-mutation-css-dead` ⇒ 它立刻出现在真死候选里
（49 条），还原后回到 46 条。⇒ 这把尺会对"选择器指向不存在的元素"这件事真的响。

**为什么还没删**：46 条逐条要有说法。已知的假阳性来源至少三个 —— 服务端返回的 HTML 里带的类名、
由拼接产生但前缀形态我没覆盖的、以及只在某个章节/某个弹层才渲染的。**说不清"它在哪一屏才有元素"的，
就标「暂不判」，不删。**

## 六、删掉第一批死样式（35 处 / 2781 字符）

`node tools/css-dead-rules.mjs --triage` 给每条真死候选一个说法，三个假阳性源逐个查：

| 判定 | 条数 | 依据 |
|---|---|---|
| 整族死 | 35 | 同一前缀的兄弟类**一个都不在 JS 里** ⇒ 整块组件没人造得出来 |
| 暂不判 | 11 | 有活的兄弟（`.dkar` 的兄弟 `dkact` 活着、`.contc` 的 `cont` 活着）⇒ 可能是还没做的变体，**留着** |

整族死的那几族：`.ob*`（obtxt/obtags/obbtns/obimg/obcap/obc/obdots —— 一整个"观察"组件）、
`.ds-*` / `.dm-*`（ds-fire / ds-jea / dm-att / dm-tru / dm-jea / dm-gru / dm-ten …，
看着是**旧版情绪系统**的形态类，现役的 `app98_emotion.js` 用的是别的名字）、
`.fdesc` / `.fmeta` / `.fcta` / `.fpills` / `.hfseg` / `.dkdots` / `.dkbtns` / `.chprev`。

**删之前做的一次手工核对救了这条结论**：`chprev` 在 PowerShell 的全仓搜索里"命中"了
`app27_choice.js`，看着像有人用 —— 但 PowerShell 的 `Select-String` **默认不区分大小写**，
真正的命中是函数名 `chPreview`（和元素 id `chTxt`），**类名 `.chprev` 没人用**。
⇒ 判「有没有人用」必须区分大小写（node 的 `indexOf` 是对的，`Select-String` 要加 `-CaseSensitive`）。

结果：`shell.html` 166646 → 163865 字符，删 35 处规则，两个判据同时过
（生效值快照 780 格逐字节一致 · `check-all` 全绿）。

**射程说明**：快照只覆盖 30 个探针元素，删掉的这些类**都不在探针里** ——
所以这次是"证据"（整族无引用）在兜底，不是"闸"在兜底。这也是为什么删的是整族而不是零散几条：
整族死可以说清机制，零散死说不清。

## 七、做的时候注意（现在不用做，但别忘）

- **不重排注入顺序**：65 个 `<style>` 的先后就是层叠顺序，任何"整理"只要动了顺序，就等于动了样式。
- **不合并条件注入**：`app92_mustlogin.js:13` 那种 `if (…)(function(){…})()` 是有条件的，
  拼进静态表会让它在不该出现的时候出现。
- **不动 `creator_embed.js` 里那段**：那是嵌入的 Creator 页面自己的 HTML，不是本页的样式。
