# 剧本文件包（miru.package/1）

> 给创作者看的提交格式。依据《MIRU 互动剧本写作规范 v2》（2026-11-14）。
> 目标：一个 zip 交齐「剧本 + 照片 + 视频 + 音乐 + 互动游戏」，系统按剧本里的位置自动挂好，校验后直接发布。

## 1. 包里放什么

```
我的作品.zip
├── manifest.json        作品资料：标题、简介、人物卡、素材表
├── script.md            只放剧本正文（不夹设定、不夹素材表）
└── assets/
    ├── cover.jpg
    ├── opening.mp4
    ├── bg/c01s01.jpg …
    ├── cg/c01.jpg …
    ├── char_adrian.jpg …
    ├── bgm/tense.mp3 …
    └── games/find_ring.json …
```

也接受 `bible.json` 作为作品资料文件名（和官方后台同一套字段）。文件名本身不重要，`manifest.assets` 负责把文件映射到剧本槽位。

## 2. 素材挂到哪里

剧本里的标签决定位置，素材表的键必须和标签里的槽位**逐字一致**：

| 剧本里写 | 素材表键 | 文件 | 规范要求 |
|---|---|---|---|
| `⟦BG\|bg_c03s02\|卧室·深夜⟧` | `bg_c03s02` | 图 | 紧跟 `# SCENE`；竖屏 9:16；带在场人物；画面无文字 |
| `⟦CG\|CG_RAIN\|雨里的他⟧` | `CG_RAIN` | 图 | 同一场里的特写，不换背景 |
| `⟦VIDEO\|vid_open\|开场⟧` | `vid_open` / `opening_video` | 视频 | 可选；没有就跳过 |
| `⟦BGM\|BGM_TENSE\|紧张⟧` | `BGM_TENSE` 或 `bgm_BGM_TENSE` | 音频 | 场开头；情绪大转折才换 |
| `⟦MG\|g_find_ring\|找戒指⟧` | `g_find_ring` | 游戏 JSON | 一章最多 1 个；赢输都要有后果 |
| `⟦CHAR\|罗温\|m\|34\|…⟧` | `char_罗温` 或 `char_rowan`（人物卡 `key`） | 立绘 | 文件名 `char_key`，竖屏 9:16 |

命名按规范：背景 `bg_c章号s场号`（如 `bg_c03s02`），立绘 `char_key`。

## 4. 发布前会自动检查

发布时按规范 v2 跑一遍，**错误会挡住发布，提示会显示在回执里但不挡**：

- 剧本：章节标记、每章 `# CHOICE`、`# ·` 收尾、`⟦CALL⟧` 闭合、未知指令、取向声明
- 场景：每个 `# SCENE` 下一行必须是 `⟦BG⟧`
- 结构建议：15–20 章、每章 3–5 场、每章最多 1 个小游戏
- 素材：每个 `BG / CG / VIDEO / BGM / MG` 槽位是否有文件；多出来的文件会列出
- 人物：剧本角色是否有人物卡、是否有立绘
- 尺度：服务端 `safety()`（露骨、未成年）另跑一次

## 5. 缺素材怎么办

- **封面**：没交就用第一张真的上传了的背景兜底。
- **视频**：可选，缺失只提示。
- **背景 / CG / 音乐 / 游戏**：缺失会列在回执的 `qa.assets.missing` 里，播放时跳过或由 AI 兜底；不影响先发布、后补。
- **人物卡 / 立绘**：缺失只提示；没有卡的角色不会出现在「发现 → 角色」。

## 6. 发布通道

客户端上传每个素材到 `/api/pkg`（按槽位存，不按素材库、不按件扣费），再把 `script + assets + characters` 一起提交到 `/api/works`。作品在运行时优先读包里的素材表，官方剧的 `art/official/<work>.json` 路径保持不变。
