# 旁白与上下文压缩试点

试点作品：零点王冠（w_scmw7f7e4565778126fa）。其他作品没有配置时继续走原逻辑。两个功能分别由作品圣经的 experience.narration / experience.context（schema: 1, enabled: true）控制；关闭开关后下一次加载即恢复原路径，不改写历史聊天。

## 玩家会看到什么

角色仍各自生成动作和台词。关键选择或有可见动作的回合，在角色演完后按需补一小段场景旁白，每次至多 90 字、至少隔 3 轮。章节开场卡、作者事件、入场说明或玩家感官已描写过这一刻时不补；快速回复、心声、纯台词、失败回合及收束回合不加额外请求。旁白不重演角色、不替玩家行动，也不负责发放道具、公开秘密或转场。

## 生成、证据与失败

旁白只接收当前地点、时间、实际在场人物和本轮已送达的公开动作台词；不接收完整圣经、未来章节、角色卡、导演意图、选择效果或玩家心声。模型返回 text 与来源编号。编号、人物、长度、玩家主语和动作词汇均经过程序检查；内容词需有被引用的实际角色动作支持，连接和镜头用语用小范围词表。词汇来源校验是保守过滤，不能证明任意句子的语义；无法确认就跳过，不为凑频率强写。

额外调用用 quick 档、220 输出 token、5 秒硬上限，只调一次。optional 请求不修改全局 AI 错误状态、不弹失败提示、不自动重试。迟到回复核对线程、场景、b98 对象、轮次和消息边界。旁白在 turn98 封装该轮之前提交，跟随重新生成候选和回滚。

## 上下文压缩

上下文保留最近片段，加可追溯的历史摘录和程序状态。摘录保留原话的“承诺、猜测、声明”性质；只把小游戏等程序回执写成已发生事件。玩家心声、私人体感和氛围旁白不成为角色共同事实。每条新消息保存实际见证人，角色只收到自己可见的历史；旧存档没有见证信息时采取保守范围，不把过去所有聊天倒灌给后来出现的人。

压缩是本地摘录，不额外调用模型、不删除原始聊天；原有全局模型摘要不会复制进每个角色。关键选择、边界和回执有独立保留路径。上下文、来源和旁白统计都放在 b98 中，跟随存档与回复版本恢复。

## 验证与扩展条件

- 非试点作品：模型调用、上下文和 UI 行为保持原样。
- 旁白：实际角色回复先出现；来源受限；已有叙事去重；超时失败不影响剧情；换章、换线程、重新生成后丢弃迟到结果。
- 长聊天：记录真实输入字符前后值，验证见闻隔离、边界保留、承诺没有变完成；字符数量不是 token 数量。
- 用隔离浏览器和受控回答验证整轮回复、保存重开及候选切换，再采少量合成场景的真实模型输出检查可读性和时延。
- 完成人工试玩后再给其他作品添加配置；本次不会批量开启。
