# 旁白与上下文压缩试点

试点作品：零点王冠（w_scmw7f7e4565778126fa）。其他作品不批量开启。作品圣经的 experience.narration / experience.context（schema: 1, enabled: true）分别控制两项功能。

## 玩家会看到什么

角色分别给出动作和台词，再显示带“旁白”标签的一段独立文字。进场、每场首次关键选择有专门的旁白位置；普通成功回复默认每 3 轮一次。快速聊天、纯台词和普通动作也能使用这个位置。已有作者事件、入场旁白或 box 内的作者旁白会显示标签并计入本轮，避免重复添加。心声、失败回复和退出收束不强写旁白。

实际截图检查另覆盖旁白标签、深色底板与金色边线，避免被背景画面淹没。

旧 pk / agent97 存档直接按作品 ID 启用，不改引擎、不换角色 ID、不迁移或清除玩家进度。老版本的旁白计数首次升级为 version:2 时重置显示冷却，让下一次成功回复能够显示。打开旧局预热配置，回复前最多等 1.5 秒；失败配置可重试，慢配置不锁死对话。试点作品的内置默认配置保证公开资料暂时不可用时仍可使用旁白；读取到显式关闭配置后以关闭为准。

## 来源和生成协议

旁白只接收当前公开地点、实际在场人物、本轮已送达的公开表演；仅进场可使用已经展示的当章导语。后续聊天不复用旧开场。不会提供完整剧本、未来章节、角色秘密、导演意图、选择效果、心声或私密感官。

模型返回 {source, kind, topic}，选择一个公开镜头。程序保留选中动作的完整限定条件和主体，或将原台词中连续出现的短话题放进明确的台词归属句式。模型附带的任意自由 text 都不发布。不能用词汇重合证明动作主体正确，也不靠动作关键词推断他人已经做了什么。

模型请求用 quick 档，220 输出 token、5 秒硬上限，只调一次。失败、超时或选择不合格时，依据本轮真实回复者生成短衔接旁白；不依赖特定动作、分词 API 或额外重试。降级文字较朴素，后续根据试玩再扩充作者镜头素材。

每次发布都检查长度、线程、当前场景、状态对象、轮次和消息边界。迟到结果不插入已切换的对话。b98 在 turn98 封装前提交；pk 在 reply 忙锁和 reply73 快照内提交。agent97 沿用原有回合流程，不额外开启版本再生。已有作者叙事保留事实身份；新增镜头标记 narrative135.kind=style。模型选择成功和降级分别计数，只有实际显示才消耗冷却。

## 上下文压缩

b98 试点的模型输入使用最近片段、可追溯历史摘录和程序状态。原始聊天不删除，不额外调用压缩模型。每条公开消息记录当时的实际见证人，角色只收到自己能知道的内容；旧历史没有见证信息时采用保守范围。承诺、猜测和行动尝试保留其原性质，不作为完成回执。心声、私人体感和新添氛围旁白不成为共同事实。

关键选择、边界和程序回执独立保留。上下文统计与 b98 存档和回复版本一起恢复。旧 pk / agent97 本次接入旁白，保留原有上下文机制。

回合锁在重复加载时保留原实例和 busy 绑定，避免旧局在阅读未完成前被当作空闲。试点导演给出短角色 ID 时先按当前在场角色归一；公开回合没有有效出场名单时由实际被点名或首位在场角色接话，不能引入不在场人物。

## 验证和推广

- 自测覆盖普通动作、仅台词、仅动作、进场、重要选择、作者旁白标签、私密隔离、承诺归属、模型超时、迟到结果和旧存档。
- 受控浏览器验证两角色回复后的降级、真实标签、保存和回滚、历史阅读位置与“回到最新”。
- 独立真实模型浏览器工具 tools/narration135-live.cjs：隔离测试读者和账户请求，保留真实 ask、导演、角色及线上模型传输；验证开场、续玩 UI 发送和旧 pk 局。它不使用预设模型回答。生产复验可用 MIRU_LIVE_ORIGIN=https://miru.plus；网络代理通过 MIRU_TEST_PROXY 指定。
- 字符压缩统计不是 token 数。当前长聊天回归的导演历史与记忆部分由 3012 降至 2264 字符，角色最大部分由 3616 降至 1217 字符。
- 实际试玩通过后再决定其他作品的配置；本次仅保留零点王冠试点。
